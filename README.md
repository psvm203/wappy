# Wappy

친구들의 캐릭터가 바탕화면과 다른 앱 위를 돌아다니는 macOS·Windows용 Tauri 앱입니다. 사이드바에서 친구와 캐릭터를 관리합니다.
초대 코드로 친구를 연결하고, 이름·캐릭터·상태 메시지와 접속 상태를 공유합니다.

## 실행

Node.js **24 이상**, pnpm 11.25.0, Rust stable과 [Tauri 개발 환경](https://v2.tauri.app/start/prerequisites/)이 필요합니다. macOS는 Xcode Command Line Tools, Windows는 Visual Studio C++ Build Tools와 WebView2를 설치하세요.

```sh
pnpm install
pnpm desktop
```

공통 API를 빌드하고 서버(`localhost:3001`), Vite(`localhost:1420`), Tauri 앱을 함께 실행합니다. 처음 실행할 때는 Rust 의존성 컴파일에 시간이 걸립니다.

브라우저에서 UI와 친구 연결을 확인하려면 `pnpm dev` 실행 후 `http://localhost:1420`을 여세요. 일반 창과 시크릿 창을 사용하면 서로 다른 두 프로필로 테스트할 수 있습니다. 바탕화면 캐릭터, 메뉴 막대·트레이, 고정·최소화·숨김·창 크기 변경은 `pnpm desktop`으로 실행한 Tauri 앱에서 동작합니다.

1. 이름과 캐릭터를 선택합니다. 최초 화면의 **연결할 서버**에서 친구와 같은 서버를 지정할 수 있습니다.
2. **초대하기 → 초대 코드 만들기 → 초대장 복사**에서 서버 주소와 코드가 담긴 초대장을 복사해 친구에게 전달합니다.
3. 처음 사용하는 친구는 첫 화면의 **초대받았어요**에 초대장 전체를 붙여넣고, 표시된 서버를 확인한 뒤 이름과 캐릭터를 선택합니다. 해당 서버에서 프로필을 만들고 친구와 연결합니다. 이미 프로필이 있다면 **초대하기 → 초대를 받았나요?**에 붙여넣으세요. 연결되면 친구의 캐릭터가 내 바탕화면에도 나타납니다.
4. **내 모습**에서 캐릭터와 상태를 바꾸거나 **접기**로 관리 사이드바를 줄일 수 있습니다.
5. **내 모습 → 복구 코드 발급·교체**에서 복구 코드와 서버 주소를 안전하게 보관하세요. 기기를 바꾸거나 앱 저장소가 지워졌을 때 첫 화면의 **다시 돌아왔어요**에서 같은 프로필과 친구 목록을 불러올 수 있습니다.
6. **내 모습 → 함께할 서버 → 프로필 보관하고 서버 바꾸기**에서 현재 프로필을 기기에 보관하고 다른 서버에서 시작할 수 있습니다. 첫 화면의 **다시 만나요**에서 보관한 이름과 서버를 선택하면 기존 친구 목록으로 돌아옵니다. 서버가 응답하지 않을 때도 **서버 설정 보기**에서 전환할 수 있습니다.
7. **친구들 → 인사 보내기**로 친구에게 손 인사를 보낼 수 있습니다. 받은 인사는 친구 카드와 친구들 탭의 개수, 바탕화면의 해당 친구 캐릭터에 **👋 안녕!** 말풍선으로 표시됩니다. 친구 카드에서 **확인**을 누르면 말풍선과 새 인사 표시가 사라집니다.

친구가 오프라인이어도 인사를 남길 수 있습니다. 같은 친구에게 30초에 한 번 보낼 수 있고, 서버는 방향별로 가장 최근 인사 하나를 최대 24시간 보관합니다. 앱·서버를 다시 시작하거나 프로필을 복구해도 확인하지 않은 인사는 유지됩니다. 인사를 받았다고 사이드바를 열거나 소리를 내지 않으며, 캐릭터 숨김·일시정지 설정도 유지합니다. 확인 처리는 수신자만 할 수 있고 친구 연결을 해제하면 양쪽 인사가 함께 삭제됩니다. 인사를 사용하려면 서버와 앱 모두 이 기능이 포함된 버전이어야 합니다.

바탕화면의 **👋 안녕!** 말풍선을 누르면 사이드바의 해당 친구 카드로 바로 이동합니다. 숨기거나 최소화한 사이드바도 열리고, 접어 둔 경우 펼쳐집니다. 말풍선을 여는 것만으로 인사를 읽음 처리하지 않으며, 친구 카드에서 **확인**하거나 인사를 보낼 수 있습니다. 연결이 끊겨도 이미 받은 인사는 열어 볼 수 있고, 확인·전송은 다시 연결된 뒤 사용할 수 있습니다. 다른 서버·프로필로 전환했거나 친구 연결이 해제된 뒤 도착한 오래된 바로가기 요청은 무시합니다.

**친구들 → 이름이나 상태로 찾기**에서 친구를 검색하고 **전체 / 접속 중 / 새 인사**로 목록을 좁힐 수 있습니다. 여러 단어를 입력하면 이름과 상태에 그 단어가 모두 포함된 친구를 찾으며, 영문 대소문자는 구분하지 않습니다. **새 인사**는 최근에 받은 순서로 표시하고 확인한 인사는 목록에서 빠집니다. 결과가 없으면 **필터 초기화**로 전체 목록으로 돌아올 수 있습니다.

검색과 필터는 사이드바에만 적용하며 바탕화면 캐릭터 선택과 인사의 읽음 상태를 바꾸지 않습니다. 연결이 끊겨도 마지막으로 받은 이름·상태·인사를 검색할 수 있고, **접속 중** 목록에는 상태를 확인할 수 없다는 안내를 표시합니다. 앱을 다시 열거나 프로필을 전환하면 검색 조건을 초기화합니다. 친구를 새로 연결하거나 바탕화면 인사 바로가기로 이동할 때도 조건을 풀어 해당 친구를 찾을 수 있게 합니다.

**친구들** 또는 **내 모습 → 친구에게 접속 상태 보이기**를 끄면 친구에게 오프라인으로 표시됩니다. 내 캐릭터는 계속 움직이고 친구 목록과 인사도 계속 받을 수 있습니다. 직접 보내는 인사와 프로필 변경은 친구에게 전달됩니다. 기본값은 공개이며, 변경한 설정은 서버의 해당 프로필에 저장되어 앱·서버 재시작, 서버 전환 후 복귀, 프로필 복구 후에도 유지됩니다. 친구 목록에는 숨김 여부를 별도로 표시하지 않습니다.

저장이 완료되면 상단에 **접속 숨김**이 표시되고 접은 사이드바에서도 확인할 수 있습니다. 친구 화면에는 다음 상태 조회 때 반영됩니다. 저장 응답을 받지 못하면 서버 상태를 다시 확인하며, 이마저 실패하면 공개 상태를 알 수 없다고 표시하고 **접속 공개 상태 다시 확인**을 제공합니다. 네트워크가 끊겼을 때는 공개 설정을 바꿀 수 없습니다. 설정을 지원하지 않는 이전 서버에서는 조작을 비활성화합니다.

나와 접속 중인 친구들의 캐릭터는 별도의 투명 창에서 화면의 네 가장자리를 따라 걷습니다. 발은 가까운 가장자리를 향하고, 바닥·벽·천장에 맞춰 중력 방향이 바뀌어 걸음마다 가장자리로 내려앉습니다. 모퉁이에서는 몸이 부드럽게 회전하며 다음 가장자리로 넘어갑니다. 캐릭터마다 출발 위치가 다르고, 3~8초마다 각자 무작위로 걷는 방향과 속도를 바꾸거나 잠깐 쉬었다 다시 걷습니다. 드래그하거나 공중에 떠 있을 때는 무작위 행동이 개입하지 않습니다.

캐릭터를 드래그해서 옮길 수 있습니다. 빠르게 움직이다 놓으면 마지막 드래그 방향과 속도로 날아가며, 가까운 가장자리로 끌려가 튕기고 감속한 뒤 다시 걷습니다. 잠시 잡고 있다 놓으면 던지지 않고 떨어뜨립니다. 이름표는 몸이 회전해도 똑바로 표시됩니다.

이 창은 사이드바가 놓인 모니터의 작업 영역을 덮습니다. 캐릭터와 인사 말풍선 위에서 마우스 입력을 받고 빈 공간의 클릭과 키보드 입력은 아래 앱으로 전달합니다. 사이드바를 다른 모니터로 옮기면 캐릭터의 활동 영역도 따라갑니다. 캐릭터 창에는 배경이 없습니다.

사이드바를 접거나 최소화해도 캐릭터는 계속 표시됩니다. 친구 탭의 **잠깐 쉬기**·**캐릭터 숨기기**로 제어하며, 접은 사이드바에서도 같은 버튼을 사용할 수 있습니다. 움직임과 표시 설정은 기기에 저장되어 재실행해도 유지됩니다. 서버 연결이 끊겨도 내 캐릭터는 계속 걷고, 오프라인 친구는 제자리에서 쉽니다. OS의 동작 줄이기가 켜져 있으면 저장된 설정과 관계없이 자동 이동을 일시정지한 상태로 시작하지만 **다시 걷기**로 직접 시작할 수 있습니다.

일시정지 중에는 캐릭터의 반복 화면 갱신을 중단합니다. 표시한 캐릭터가 모두 오프라인이면 던지기·회전이 끝난 뒤 갱신을 중단하고, 친구가 돌아오거나 다시 드래그할 때 필요한 움직임을 재개합니다. 정지 중에도 캐릭터를 드래그하고 모니터 크기에 맞춰 위치를 조정할 수 있으며, 마우스 위치 조회와 친구 상태 수신은 유지됩니다.

데스크톱 앱의 **친구들 → 캐릭터 선택**에서 나와 친구의 캐릭터를 각각 선택할 수 있습니다. **내 캐릭터만**으로 화면을 줄이거나 **모두 선택**으로 되돌릴 수 있습니다. 선택 해제한 캐릭터와 그 말풍선은 바탕화면에서 숨겨지지만, 친구 목록과 받은 인사는 사이드바에 남습니다. 선택을 모두 해제하면 바탕화면 캐릭터의 애니메이션과 마우스 위치 조회도 중단합니다. 전체 **캐릭터 숨기기 / 표시**는 선택한 대상을 유지한 채 표시만 전환합니다.

캐릭터 선택은 이 기기의 서버·프로필별로 저장합니다. 같은 기기에서 프로필을 다시 선택하거나 복구해 로그인 토큰이 바뀌어도 선택을 유지하며, 다른 프로필·서버·기기의 선택에는 영향을 주지 않습니다. 새 친구는 기본으로 선택됩니다. 네트워크가 끊겨도 선택을 바꿀 수 있습니다. 저장에 실패하면 화면에는 적용하고 오류를 안내하며, 저장된 값을 읽지 못하면 모두 선택한 기본값과 안내를 표시합니다. 읽기 실패만으로 기존 저장값을 덮어쓰지 않습니다.

**× 버튼과 창 닫기는 사이드바만 숨깁니다.** macOS 메뉴 막대 또는 Windows 알림 영역의 Wappy 아이콘에서 **사이드바 열기**, **잠깐 쉬기 / 다시 걷기**, **캐릭터 숨기기 / 표시**를 사용할 수 있습니다. 트레이와 사이드바는 같은 설정을 제어합니다. **Wappy 종료**를 선택하면 캐릭터 창과 프로세스까지 함께 종료됩니다. 숨긴 상태에서 앱을 다시 실행하면 기존 사이드바가 나타나며 중복 실행되지 않습니다. macOS에서는 Dock 아이콘으로도 다시 열 수 있습니다.

데스크톱 앱의 첫 화면 또는 **내 모습 → 다음에도 함께 시작해요**에서 **컴퓨터 로그인 시 Wappy 실행**을 켤 수 있습니다. 최초 실행만으로 등록하지 않으며, 사용자가 선택할 때 현재 OS 사용자에게만 등록합니다. 자동으로 시작할 때는 사이드바를 숨기고 트레이와 캐릭터 창을 실행합니다. 캐릭터의 움직임·표시 설정과 마지막에 선택한 프로필은 유지됩니다. 자동 실행이 중복 요청되어도 숨긴 사이드바를 열지 않으며, 직접 앱을 실행하거나 트레이를 선택하면 다시 열립니다.

설정 화면을 열거나 앱으로 돌아오면 OS의 등록 상태를 다시 읽습니다. 변경이 실패해도 상태를 다시 확인하며, 상태를 읽지 못하면 선택을 잠그고 **자동 실행 상태 다시 확인**을 제공합니다. 앱을 사용할 위치에 설치한 뒤 켜고, 앱을 옮기기 전에는 꺼 주세요. macOS에서는 사용자 `Library/LaunchAgents/com.wappy.client.plist`에 등록하며 OS의 백그라운드 실행 허용은 별도로 적용될 수 있습니다. Windows에서는 현재 사용자의 `Run` 항목에 경로를 따옴표로 감싸 등록하고, 작업 관리자의 해당 앱 시작 허용 상태도 확인합니다. 컴퓨터 전체의 시작 설정은 변경하지 않습니다. [Apple Launch Agents](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html), [Microsoft Run 키](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)

Windows 제거 프로그램은 삭제하는 앱의 실행 경로를 가리키는 자동 실행 등록과 작업 관리자 설정을 함께 정리합니다. 업데이트 모드와 기존 앱을 지우지 않는 재설치에서는 기존 설정을 유지하며, 다른 설치 경로를 가리키는 등록은 지우지 않습니다. 설치 중 기존 앱을 먼저 제거하는 옵션을 선택했다면 다시 설치한 뒤 자동 실행을 켜 주세요. macOS에서 앱을 삭제할 때는 자동 실행을 먼저 꺼 주세요.

캐릭터 창은 사이드바와 일반 앱 창보다 앞에 표시됩니다. 사이드바를 클릭하거나 고정 설정을 바꿔도 캐릭터가 그 뒤로 가려지지 않습니다.

사이드바는 처음에 현재 모니터의 작업 영역 오른쪽에 배치되며, 화면 배율·작업 표시줄·Dock을 고려합니다. 상단 로고와 빈 공간을 드래그해 옮길 수 있고, 접은 상태에서는 위쪽의 **⠿** 손잡이를 드래그하면 됩니다. 접거나 펼치면 현재 모니터 오른쪽으로 다시 정렬됩니다. 항상 위에 표시 설정은 상단 버튼으로 바꿀 수 있습니다.

| 경로           | 역할                                                                 |
| -------------- | -------------------------------------------------------------------- |
| `apps/client`  | React 관리 사이드바, Tauri 투명 캐릭터 창, 기기 내 세션 저장         |
| `apps/server`  | Node HTTP API, SQLite 영속 저장, 접속 상태                           |
| `packages/api` | `@wappy/api`: 메서드·경로별 요청/응답 타입, 캐릭터 목록, 프로필 검증 |

클라이언트의 `request()`와 서버의 `reply()`가 같은 `ApiRoutes`를 참조합니다. 타입 변경은 두 앱의 타입 검사에 반영되며, 서버는 외부 JSON을 런타임에도 검증합니다. 모든 요청과 응답은 JSON입니다.

| 메서드·경로            | 요청                          | 응답                                                           |
| ---------------------- | ----------------------------- | -------------------------------------------------------------- |
| `POST /session`        | `{ name, character, status }` | `{ token, profile }` (201)                                     |
| `POST /session/recover` | `{ code }`                    | `{ token, profile }`                                          |
| `POST /recovery-code`   | `{}`                          | `{ code }` (201)                                              |
| `GET /state`           | 없음                          | `{ self, friends: [{ id, name, character, status, online }] }` |
| `PATCH /profile`       | `{ name, character, status }` | 프로필                                                         |
| `PATCH /presence`      | `{ sharing }`                 | `{ sharing, revision }`                                        |
| `POST /invites`        | `{}`                          | `{ code, expiresAt }` (201)                                    |
| `POST /invites/accept` | `{ code }`                    | 연결된 친구의 프로필                                           |
| `POST /friends/remove` | `{ friendId }`                | `{ ok: true }`                                                 |
| `POST /friends/wave`   | `{ friendId }`                | `{ id, sentAt }` (201)                                          |
| `POST /waves/read`     | `{ waveId }`                  | `{ ok: true }`                                                 |
| `GET /health`          | 없음                          | `{ ok: true }`                                                 |

`POST /session`, `POST /session/recover`, `GET /health`, CORS preflight를 제외한 요청은 `Authorization: Bearer <token>`이 필요합니다. 오류는 `{ error: string }`과 400/401/403/404/409/413/415/429/500 상태 코드로 반환합니다. 이름은 1–24자, 상태는 최대 60자, 캐릭터는 `bunny`, `cat`, `bear`, `frog` 중 하나입니다.

초대 코드는 24시간 동안 한 번만 사용할 수 있습니다. 다시 만들면 이전 코드가 무효화되며, 본인 초대와 중복 연결은 거부합니다. 친구 연결과 코드 소비는 하나의 SQLite 트랜잭션으로 처리됩니다. 연결 해제는 양쪽 목록에 반영됩니다.

`GET /state`의 친구 항목에는 확인하지 않은 인사가 있을 때만 `wave: { id, sentAt }`이 포함됩니다. `sentAt`은 서버의 Unix 밀리초 시각입니다. 조회만으로 인사를 소비하지 않으므로 응답이 유실되어도 다음 조회에서 다시 받습니다. `/waves/read`는 정확히 일치하는 인사 ID만 확인 처리하며 반복 요청은 안전합니다. 이전 인사의 늦은 확인 요청이 새 인사를 지우지 않습니다. 친구별 전송 간격은 SQLite에서 원자적으로 제한하며, 너무 빠른 요청에는 429와 `Retry-After`를 반환합니다.

`GET /state`의 최상위 `presence: { sharing, revision }`은 인증한 프로필 자신의 접속 공개 설정입니다. 친구의 설정이나 마지막 접속 시각은 응답에 포함하지 않습니다. 숨긴 프로필은 계속 조회하거나 인사를 보내도 친구의 `online`이 `false`이며, 다시 공개하면 마지막 통신 시각에 따른 일반 접속 상태로 돌아갑니다. `/presence`는 본인의 설정만 변경하고, `/profile`이나 세션 복구는 이를 변경하지 않습니다. `revision`은 변경할 때마다 증가하여 늦은 조회 응답이 최근에 확인한 설정을 덮어쓰지 않게 합니다.

초대장은 서버 주소와 초대 코드만 담은 텍스트이며 로그인 토큰이나 복구 코드는 포함하지 않습니다. 기존 코드만 입력하는 방식도 사용할 수 있으며, 이때는 서버 주소를 직접 맞춰야 합니다. 이미 로그인한 프로필은 다른 서버의 초대장을 받아도 서버를 바꾸거나 토큰을 보내지 않고 안내합니다. 첫 친구 연결에 실패해도 생성한 프로필은 유지되므로 초대 화면에서 코드를 확인하고 다시 시도할 수 있습니다. 응답을 받지 못했다면 **친구들** 목록에서 연결 여부도 확인하세요.

상태는 5초 간격으로 가져오며 마지막 조회로부터 30초가 지나면 오프라인으로 표시됩니다. **데스크톱 앱은 Rust 백그라운드 작업에서 조회하므로 사이드바의 숨김·최소화와 WebView 타이머 제한에 의존하지 않습니다.** 네트워크가 끊기면 재시도하고 오래된 접속 상태를 온라인으로 표시하지 않습니다. 컴퓨터 자체가 잠자기 상태에 들어가거나 네트워크가 끊긴 동안에는 오프라인으로 표시되며, 다시 통신할 수 있게 되면 자동으로 갱신됩니다. 브라우저 미리보기는 웹 타이머로 조회하므로 브라우저의 백그라운드 제한이 적용될 수 있습니다.

데스크톱 조회 요청은 10초 안에 완료되지 않으면 취소하고 재시도합니다. 응답은 최대 1MiB까지 받으며, 캐릭터·프로필·친구 목록의 형식을 확인한 뒤 화면에 반영합니다. 인증 토큰을 다른 곳으로 보내지 않도록 상태 조회의 HTTP 리디렉션은 따라가지 않으므로 최종 서버 주소를 입력하세요. 인증이 만료되면 재시도를 멈추고 복구 화면을 안내합니다. 계정 변경, 페이지 새로고침, 앱 종료 시 이전 조회 작업이 중단됩니다.

서버 접속 상태는 메모리에만 저장하므로 서버 재시작 직후에는 각 앱이 다시 조회할 때 갱신됩니다. 단일 서버 프로세스를 기준으로 합니다.

## 서버 설정과 데이터

`apps/server/.env.example`을 `apps/server/.env`로 복사해 설정할 수 있습니다.

| 변수              | 기본값                | 설명                                 |
| ----------------- | --------------------- | ------------------------------------ |
| `HOST`            | `127.0.0.1`           | 외부 연결을 받으려면 `0.0.0.0` 사용  |
| `PORT`            | `3001`                | API 포트                             |
| `DATABASE_PATH`   | `./data/wappy.sqlite` | 서버 작업 디렉터리 기준 SQLite 경로  |
| `ALLOWED_ORIGINS` | 없음                  | 추가 웹 클라이언트 Origin, 쉼표 구분 |

Tauri의 macOS·Windows Origin과 로컬 Vite Origin은 기본 허용됩니다. 운영 서버는 HTTPS 리버스 프록시 뒤에 두고, 친구 모두 접근할 수 있는 **동일한 서버 주소**를 사용하세요. 클라이언트 기본 주소는 `apps/client/.env`의 `VITE_API_URL`로 지정하거나 최초 화면에서 입력합니다. `localhost`는 각자의 컴퓨터이므로 서로 다른 기기에서 사용할 공용 서버 주소가 아닙니다. 서버는 자동으로 배포되지 않습니다.

```sh
pnpm build
pnpm --filter server start
```

서버는 별도 프레임워크나 DB 서비스 없이 Node의 [내장 SQLite](https://nodejs.org/api/sqlite.html)를 사용합니다. 사용자·친구·유효한 초대·복구 코드·인사·접속 공개 설정은 SQLite에 저장하며 세션 토큰, 초대 코드, 복구 코드는 SHA-256 해시로만 저장합니다. 기존 데이터베이스는 시작 시 복구 코드·인사·접속 공개 설정 테이블을 추가해 그대로 사용할 수 있습니다. 쓰기 요청은 4KB로 제한하고 IP별 요청 횟수를 제한합니다. 세션 생성·복구 요청은 합산하여 분당 10회, 나머지 쓰기 요청은 분당 60회까지 허용합니다. 프록시의 전달 헤더는 신뢰하지 않으므로 프록시 뒤에서는 애플리케이션의 IP별 제한이 합산될 수 있습니다.

클라이언트의 기기별 토큰은 로컬 WebView 저장소에 남습니다. 앱 재실행 시 같은 프로필로 돌아옵니다. 브라우저·Tauri 개발 모드·빌드된 앱은 서로 다른 Origin의 저장소를 사용합니다. 저장소가 지워지거나 다른 기기로 옮길 때는 **미리 발급한 복구 코드와 같은 서버 주소**가 필요합니다. 코드가 없고 기존 기기에도 접근할 수 없다면 복구할 수 없습니다. 이메일 로그인은 제공하지 않습니다.

서버를 바꿀 때 현재 프로필의 로그인 정보와 표시할 이름을 이 기기에 보관합니다. 같은 서버의 서로 다른 프로필도 별도로 보관하며, 복구로 토큰이 교체되면 해당 프로필의 보관 정보만 갱신합니다. 보관에 실패하면 현재 연결을 유지합니다. 선택한 프로필만 접속 상태를 갱신하고, 보관한 나머지 프로필은 조회하지 않습니다. 보관된 프로필은 앱을 다시 실행해도 남지만, 기기 저장소가 지워지면 함께 사라지므로 복구 코드를 별도로 보관하세요.

첫 화면에서 **이 기기에서 보관 해제 → 보관 해제 확인**을 선택하면 해당 로그인 정보만 기기에서 지웁니다. 서버의 프로필과 친구 목록은 유지되며, 다시 돌아오려면 복구 코드가 필요합니다. 보관된 로그인 정보가 만료되었을 때도 기존 복구 화면으로 이동할 수 있습니다.

복구 코드는 `wappy-recovery-` 접두사와 무작위 256비트 비밀값으로 구성됩니다. 발급 화면을 떠나면 다시 표시하지 않으므로 서버 주소와 함께 비밀번호 관리자 등 안전한 곳에 보관하세요. 이 코드를 가진 사람은 프로필을 사용할 수 있으므로 친구에게 보내는 초대 코드와 구분해야 합니다. 새로 발급하면 이전 코드는 즉시 무효화됩니다. 복구 코드는 새로 발급하기 전까지 만료되지 않고 재사용할 수 있어, 복구 응답을 네트워크 오류로 받지 못해도 다시 시도할 수 있습니다.

복구할 때마다 세션 토큰을 교체하므로 기존 기기는 인증이 만료되고 수정 요청도 거부됩니다. **한 프로필의 활성 로그인 토큰은 하나**이며, 복구는 동시 기기 공유가 아닌 기기 이전입니다. 기존 기기는 ‘복구 화면으로 이동’에서 다시 복구하거나 새 프로필을 만들 수 있습니다. 친구 목록·프로필은 유지되지만, 서버 데이터가 삭제된 경우 복구 코드만으로 되살릴 수는 없습니다. 서버 백업 시 실행을 중지한 뒤 데이터 디렉터리 전체를 보관하세요.

## 빌드와 검증

```sh
pnpm build
pnpm check-types
pnpm test
pnpm lint
cargo fmt --manifest-path apps/client/src-tauri/Cargo.toml --check
cargo check --manifest-path apps/client/src-tauri/Cargo.toml
cargo test --manifest-path apps/client/src-tauri/Cargo.toml --lib --locked
pnpm --filter client tauri build
```

Tauri 패키지는 해당 운영체제에서 빌드합니다. `.github/workflows/check.yml`은 macOS·Windows 각각에서 타입 검사, 빌드, API 통합 테스트, Rust 테스트와 실제 창·트레이·백그라운드 연결 검사를 실행한 뒤 설치 프로그램을 만듭니다. Windows에서는 이어서 공백·한글 경로에 실제 설치하고 배포용 앱의 창이 열리는지 확인합니다. 설치만으로 자동 실행을 켜지 않는지, 업데이트 모드(`/UPDATE`)와 덮어쓰기 재설치 시 작업 관리자 설정을 유지하는지, 제거 시 해당 설치의 자동 실행 항목만 정리하는지도 검사합니다. 이 설치 검사는 폐기되는 GitHub 호스팅 Windows 러너에서만 실행합니다. 한 운영체제의 실패가 다른 운영체제의 검사를 취소하지 않습니다.

GitHub Actions의 **Check Wappy → Artifacts**에서 해당 커밋의 테스트용 설치 파일을 받을 수 있습니다. macOS는 Apple Silicon·Intel을 모두 담은 **universal DMG**, Windows는 **x64 NSIS 설치 프로그램**입니다. Windows 설치는 현재 사용자에게 적용하고 한국어·영어를 선택할 수 있습니다. WebView2가 없으면 설치 과정에서 내려받으므로 인터넷 연결이 필요합니다. 아티팩트는 7일 동안 보관하며, 워크플로를 수동으로 다시 실행할 수도 있습니다. [Tauri Windows 설치 프로그램](https://v2.tauri.app/distribute/windows-installer/), [macOS DMG](https://v2.tauri.app/distribute/dmg/)

이 파일들은 개발자 배포 서명·Apple 공증이 없는 테스트용 빌드입니다. 일반 사용자에게 배포하기 전에는 해당 인증서를 설정하고 설치·업데이트·삭제를 실제 기기에서 검증해야 합니다. 워크플로는 GitHub Release를 발행하거나 서버를 배포하지 않습니다. 설치한 앱에서 친구와 같은 서버 주소를 입력하세요.

로컬에서 두 macOS 아키텍처를 함께 빌드하려면 다음 명령을 사용합니다. Windows에서는 해당 OS에서 `pnpm --filter client tauri build --ci --target x86_64-pc-windows-msvc`를 실행하면 `apps/client/src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/`에 설치 파일이 생성됩니다.

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
CI=true pnpm --filter client tauri build --ci --target universal-apple-darwin
```

macOS 결과물은 `apps/client/src-tauri/target/universal-apple-darwin/release/bundle/dmg/`에 생성됩니다. `CI=true`는 Finder 자동화 권한이 필요한 DMG 창 꾸미기를 생략합니다. DMG를 열고 Wappy를 Applications 폴더로 옮겨 사용하세요.

화면이 켜진 실제 데스크톱 세션에서는 프런트엔드 빌드 후 다음 검사로 트레이 생성, 닫기 후 숨김, 숨긴 상태의 제어 이벤트, 일시정지 시 애니메이션 프레임 중단과 다시 걷기 시 재개, 두 번째 실행 시 기존 창 복원, 최소화 복원과 종료를 확인할 수 있습니다. WebView의 타이머를 비활성화한 채 로컬 테스트 서버를 조회하여 접속 상태 갱신, 오류 후 재연결, 숨긴 사이드바의 접속 숨김 설정 표시와 받은 인사의 실제 말풍선 렌더링, 인사 말풍선에서 검색·필터를 해제하고 접힌 사이드바의 친구 카드로 이동·초점 복원과 오래된 요청 무시, 캐릭터 개별 선택·전체 선택 해제와 보관한 프로필의 선택 복원, 프로필 보관 후 말풍선 숨김과 조회 중단 및 재선택 후 재개, 세션 삭제 후 조회 중단도 확인합니다. 별도 앱 식별자와 비공개 WebView 저장소를 사용하므로 기존 프로필을 읽거나 변경하지 않습니다. 검사 전용 자동 실행 항목을 잠시 등록했다가 제거하며 실제 Wappy의 자동 실행 설정은 건드리지 않습니다. 잠시 테스트 창과 트레이 아이콘이 나타났다가 종료됩니다.

```sh
cargo run --manifest-path apps/client/src-tauri/Cargo.toml --example lifecycle --features tauri/custom-protocol --locked
cargo run --manifest-path apps/client/src-tauri/Cargo.toml --example lifecycle --features tauri/custom-protocol --locked -- --autostart
```

macOS의 투명 창은 `macOSPrivateApi`를 사용하므로 직접 배포를 전제로 합니다. Mac App Store 배포에는 투명 창 설정을 변경해야 합니다. [Tauri 설정 문서](https://v2.tauri.app/reference/config/#macosprivateapi)
