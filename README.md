# Wappy

친구들의 캐릭터가 바탕화면과 다른 앱 위를 돌아다니는 macOS·Windows용 Tauri 앱입니다. 사이드바에서 친구와 캐릭터를 관리합니다.
방 초대 코드로 함께 모여 이름·캐릭터와 접속 상태를 공유합니다. 같은 방의 참여자들은 서로를 볼 수 있습니다.
캐릭터는 치이카와 8종, 어벤져스 6종, 산리오 6종으로 총 20종 중에서 고를 수 있습니다. 모든 캐릭터는 걷기·드래그·오프라인 수면 표시를 지원합니다. 치이카와 캐릭터의 외형은 저장소의 [sample](sample/)에 있는 전신 참고 이미지(`*2.webp`)를 기준으로 몸의 비율·색상·표정·자세를 맞춘 SVG입니다. 하늘다람쥐의 하늘색 꼬리, 밤만쥬의 음료캔, 해달의 목도리, 헌책방이 펼쳐 든 책 등 각 캐릭터의 특징을 반영했습니다. 오프라인에서는 눈을 감은 표정으로 바뀝니다.

산리오는 [포차코](https://corporate.sanrio.co.jp/en/business-info/brands/pochacco/), [배드바츠마루](https://corporate.sanrio.co.jp/en/business-info/brands/bad_badtz-maru/), [한교동](https://corporate.sanrio.co.jp/en/business-info/brands/hangyodon/), [아히루노페클](https://corporate.sanrio.co.jp/en/business-info/brands/ahirunopekkle/), [턱시도샘](https://corporate.sanrio.co.jp/en/business-info/brands/tuxedosam/), [케로케로케로피](https://corporate.sanrio.co.jp/en/business-info/brands/kerokerokeroppi/)를 제공합니다. 공식 소개의 외형을 참고한 SVG로 검은 귀·뾰족한 머리·분홍 입술·파란 티셔츠·모자와 나비넥타이·커다란 눈과 줄무늬 옷 등 각 캐릭터의 특징을 표현했습니다. 새 프로필, 내 모습 변경, 서버 없는 체험에서 선택할 수 있습니다.

설치한 데스크톱 앱의 첫 화면에서 **서버 없이 체험하기**를 누르면 서버나 프로필 없이 캐릭터를 바로 꺼내 볼 수 있습니다. 화면 가장자리를 걷는 캐릭터를 드래그하거나 던지고, **체험 모습 바꾸기**로 이름·캐릭터를 바꿀 수 있습니다. 체험 중에는 서버 요청이나 로그인 정보 발급 없이 한 캐릭터만 표시합니다.

**체험 끝내고 시작하기**로 첫 화면에 돌아가 친구의 초대장, 새 프로필 또는 보관한 프로필로 시작하세요. 체험 모습은 체험 종료·페이지 새로고침·앱 종료 시 사라지며 기존 프로필과 캐릭터 선택에는 영향을 주지 않습니다. 창의 × 버튼은 사이드바만 숨기므로 체험 캐릭터는 계속 표시되고 트레이에서 다시 열 수 있습니다. 일시정지·숨기기는 실제 사용과 공통인 앱 설정으로 저장하며 OS의 동작 줄이기 설정도 따릅니다. 서버 없는 체험은 데스크톱 앱에서 제공하며, 친구 연결에는 아래의 서버 설정이 필요합니다.

## 실행

Node.js **24 이상**, pnpm 11.25.0, Rust stable과 [Tauri 개발 환경](https://v2.tauri.app/start/prerequisites/)이 필요합니다. macOS는 Xcode Command Line Tools, Windows는 Visual Studio C++ Build Tools와 WebView2를 설치하세요.

```sh
pnpm install
pnpm desktop
```

공통 API를 빌드하고 서버(`localhost:3001`), Vite(`localhost:1420`), Tauri 앱을 함께 실행합니다. 처음 실행할 때는 Rust 의존성 컴파일에 시간이 걸립니다.

브라우저에서 UI와 친구 연결을 확인하려면 `pnpm dev` 실행 후 `http://localhost:1420`을 여세요. 일반 창과 시크릿 창을 사용하면 서로 다른 두 프로필로 테스트할 수 있습니다. 바탕화면 캐릭터, 메뉴 막대·트레이, 고정·최소화·숨김·창 크기 변경은 `pnpm desktop`으로 실행한 Tauri 앱에서 동작합니다.

1. **카카오 로그인**으로 시작하거나 이름과 캐릭터를 선택합니다. 최초 화면의 **연결할 서버**에서 친구와 같은 서버를 지정할 수 있습니다. 카카오 로그인은 [서버 설정](apps/server/README.md#카카오-로그인-설정)이 필요하며, 같은 계정으로 다시 로그인하면 기존 프로필을 불러옵니다.
2. **초대하기 → 초대 코드 만들기 → 초대 코드 복사**에서 5자리 코드를 복사해 친구에게 전달합니다. 기본 서버 `https://wappy-api.waps.im`에서는 서버 주소를 보낼 필요가 없습니다.
3. 처음 사용하는 친구는 첫 화면의 **초대받았어요**에 코드를 입력하고 **초대장 미리 확인하기**를 선택합니다. 초대한 사람의 이름·캐릭터를 확인한 뒤 내 이름과 캐릭터로 시작하세요. 해당 서버에서 프로필을 만들고 방에 참여합니다. 이미 프로필이 있다면 **초대하기 → 초대를 받았나요? → 방에 참여하기**로 들어갈 수 있습니다. A가 B와 C를 초대하면 B와 C도 서로 보이며, B가 D를 초대해도 같은 방에 합류합니다. 프로필당 한 방에 참여하며 다른 방의 초대를 수락하면 이전 방에서 나가고 새 방의 친구들만 보입니다.
4. **내 모습**에서 이름과 캐릭터를 바꾸거나 **접기**로 관리 사이드바를 줄일 수 있습니다.
5. **내 모습 → 함께할 서버 → 프로필 보관하고 서버 바꾸기**에서 현재 프로필을 기기에 보관하고 다른 서버에서 시작할 수 있습니다. 첫 화면의 **다시 만나요**에서 보관한 이름과 서버를 선택하면 기존 친구 목록으로 돌아옵니다. 서버가 응답하지 않을 때도 **서버 설정 보기**에서 전환할 수 있습니다.
6. 내 캐릭터를 누르면 바로 위에 채팅 입력창이 열립니다. 내 이름으로 모든 친구에게 메시지를 보냅니다. Enter로 전송하고 Shift+Enter로 줄바꿈하며, Esc나 ×로 입력창을 닫습니다. 한 번에 200자까지, 1초에 한 번 보낼 수 있습니다. 친구 캐릭터를 클릭하는 공격 동작은 그대로 유지됩니다.

메시지는 보낸 순간 연결된 모든 친구에게 전달되고 보낸 사람의 캐릭터 위에 1분간 말풍선으로 표시됩니다. 채팅 메뉴·개인 채팅·메시지 신고 기능은 제공하지 않습니다. 서버는 보낸 사람별로 최근 24시간의 최대 50개를 보관하고 상태 조회에는 최신 50개를 반환합니다. 친구 화면에는 기존 상태 조회 주기에 따라 약 5초 안에 반영됩니다. 새로 연결하거나 재연결한 친구에게 이전 메시지를 공개하지 않습니다.

입력 중에는 해당 캐릭터의 움직임을 멈춥니다. 전송에 실패하거나 연결이 끊겨도 입력 내용은 유지하며, 입력창을 닫거나 프로필을 전환하면 초안은 사라집니다. 서버 없는 체험에서는 채팅을 제공하지 않습니다.

**친구들 → 이름으로 찾기**에서 친구를 검색하고 **전체 / 접속 중**로 목록을 좁힐 수 있습니다. 여러 단어를 입력하면 이름에 그 단어가 모두 포함된 친구를 찾으며, 영문 대소문자는 구분하지 않습니다. 결과가 없으면 **필터 초기화**로 전체 목록으로 돌아올 수 있습니다.

검색과 필터는 사이드바에만 적용하며 바탕화면 캐릭터 선택을 바꾸지 않습니다. 연결이 끊겨도 마지막으로 받은 이름으로 검색할 수 있고, **접속 중** 목록에는 상태를 확인할 수 없다는 안내를 표시합니다. 앱을 다시 열거나 프로필을 전환하면 검색 조건을 초기화합니다. 친구를 새로 연결할 때도 조건을 풀어 해당 친구를 찾을 수 있게 합니다.

친구 카드의 **차단하기 → 친구 차단**으로 해당 프로필과의 연결을 끊고 재연결을 막을 수 있습니다. 확인 전에는 변경하지 않으며, 차단하면 친구 캐릭터·상대가 보낸 채팅을 함께 정리합니다. 내가 전체 친구에게 보낸 메시지와 다른 친구와의 연결·대화는 유지합니다. 차단 중에는 채팅이 서로에게 전달되지 않습니다. 차단 전에 만들었거나 차단 후 만든 초대장으로도 서로 연결할 수 없습니다.

**내 모습 → 차단한 친구**에서 목록을 확인하고 **차단 해제**할 수 있습니다. 목록에는 차단 당시의 이름·캐릭터를 표시하며 상대의 프로필 변경을 따라가지 않습니다. 차단 해제만으로 친구가 되지는 않고 다시 초대를 수락해야 하며, 삭제된 과거 대화는 복원되지 않습니다. 서로 차단했다면 양쪽 모두 해제해야 연결할 수 있습니다. 차단 목록은 본인에게만 보이고 이 서버의 내 프로필에 저장되어 재시작·카카오 재로그인 후에도 유지됩니다. 연결이 끊기거나 이전 서버가 차단 기능을 지원하지 않으면 조작을 비활성화합니다.

**친구들** 또는 **내 모습 → 친구에게 접속 상태 보이기**를 끄면 친구에게 오프라인으로 표시됩니다. 내 캐릭터는 계속 움직이고 친구 목록과 채팅도 계속 받을 수 있습니다. 직접 보내는 채팅과 프로필 변경은 친구에게 전달됩니다. 기본값은 공개이며, 변경한 설정은 서버의 해당 프로필에 저장되어 앱·서버 재시작, 서버 전환 후 복귀, 카카오 재로그인 후에도 유지됩니다. 친구 목록에는 숨김 여부를 별도로 표시하지 않습니다.

저장이 완료되면 상단에 **접속 숨김**이 표시되고 접은 사이드바에서도 확인할 수 있습니다. 친구 화면에는 다음 상태 조회 때 반영됩니다. 저장 응답을 받지 못하면 서버 상태를 다시 확인하며, 이마저 실패하면 공개 상태를 알 수 없다고 표시하고 **접속 공개 상태 다시 확인**을 제공합니다. 네트워크가 끊겼을 때는 공개 설정을 바꿀 수 없습니다. 설정을 지원하지 않는 이전 서버에서는 조작을 비활성화합니다.

나와 접속 중인 친구들의 캐릭터는 별도의 투명 창에서 화면의 네 가장자리를 따라 걷습니다. 발은 가까운 가장자리를 향하고, 바닥·벽·천장에 맞춰 중력 방향이 바뀌어 걸음마다 가장자리로 내려앉습니다. 모퉁이에서는 몸이 부드럽게 회전하며 다음 가장자리로 넘어갑니다. 캐릭터마다 출발 위치가 다르고, 3~8초마다 각자 무작위로 걷는 방향과 속도를 바꾸거나 잠깐 쉬었다 다시 걷습니다. 드래그하거나 공중에 떠 있을 때는 무작위 행동이 개입하지 않습니다.

캐릭터는 걷는 속도에 맞춰 좌우로 뒤뚱거리며 발걸음마다 몸이 살짝 늘어나고 눌립니다. 마우스로 잡으면 잡은 지점을 중심으로 데롱데롱 흔들리고, 마우스를 움직이는 방향에 따라 몸이 기울었다가 서서히 가라앉습니다. 잠든 캐릭터도 드래그 중에는 매달리는 모션을 보여줍니다.

빠르게 움직이다 놓으면 마지막 드래그 방향과 속도로 날아갑니다. 비행 중에는 진행 방향으로 몸을 뻗고 속도에 따라 짧은 잔상이 나타나며, 가까운 가장자리로 끌려가 튕기고 감속한 뒤 다시 걷습니다. 잠시 잡고 있다 놓으면 던지지 않고 떨어뜨립니다. 이름표는 몸이 회전해도 똑바로 표시됩니다. 일시정지는 모션도 함께 멈추며, OS의 동작 줄이기 설정에서는 반복 모션과 비행 잔상을 표시하지 않습니다.

바탕화면의 접속 중인 친구 캐릭터를 짧게 클릭하면 내 화면에서는 서버 응답을 기다리지 않고 즉시 공격 모션을 재생합니다. 내 캐릭터가 그 친구에게 돌진하고, **팡!** 타격 효과와 함께 두 캐릭터가 반대 방향으로 튕긴 뒤 다시 걷습니다. 동시에 서버에 공격을 보내며, 서버가 승인하면 상대 화면에서도 공격한 친구의 캐릭터가 자신의 캐릭터를 공격합니다. 전송에 실패해도 내 화면의 모션은 유지하고 오류 안내를 표시합니다. 키보드로 친구 캐릭터를 선택한 뒤 Enter 또는 Space를 눌러도 공격할 수 있습니다. 두 화면의 캐릭터 위치는 각 화면의 현재 배치를 따르며, 상대에게는 기존 상태 동기화 주기에 따라 보통 5초 안에 전달됩니다.

공격은 접속 상태를 공개한 온라인 친구끼리 2초에 한 번 보낼 수 있으며, 서버와 양쪽 앱을 함께 업데이트해야 합니다. 공격 중이거나 2초 간격이 지나기 전에는 추가 클릭을 예약하지 않습니다. 이전 전송 응답을 기다리는 중에도 모션이 끝나고 2초가 지나면 다음 공격을 시작할 수 있습니다. 서버에서 돌아온 내 공격은 다시 재생하지 않습니다. 상대에게 받은 공격은 이벤트 ID로 중복 재생을 막고 짧은 대기열에서 순서대로 처리합니다. 숨긴 캐릭터·일시정지·연결 끊김 상태에서 받은 공격은 재생하지 않으며, 다시 표시할 때 몰아서 재생하지 않습니다. 공격하는 캐릭터나 대상을 드래그하거나 숨기면 그 화면의 재생을 취소합니다. 친구 삭제·차단은 양쪽의 보관 중인 공격도 삭제합니다. 내 캐릭터를 숨겼거나 공격을 보낼 수 없는 상태에서는 안내를 표시합니다.

이 창은 사이드바가 놓인 모니터의 작업 영역을 덮습니다. 캐릭터와 채팅 입력창 위에서 마우스 입력을 받고 빈 공간의 클릭은 아래 앱으로 전달합니다. 채팅 입력창이 열려 있을 때만 캐릭터 창이 키보드 입력을 받습니다. 사이드바를 다른 모니터로 옮기면 캐릭터의 활동 영역도 따라갑니다. 캐릭터 창에는 배경이 없습니다.

사이드바를 접거나 최소화해도 캐릭터는 계속 표시됩니다. 친구 탭의 **잠깐 쉬기**·**캐릭터 숨기기**로 제어하며, 접은 사이드바에서도 같은 버튼을 사용할 수 있습니다. 움직임과 표시 설정은 기기에 저장되어 재실행해도 유지됩니다. 서버 연결이 끊겨도 내 캐릭터는 계속 걷고, 오프라인 친구는 제자리에서 쉽니다. OS의 동작 줄이기가 켜져 있으면 저장된 설정과 관계없이 자동 이동을 일시정지한 상태로 시작하지만 **다시 걷기**로 직접 시작할 수 있습니다.

일시정지 중에는 캐릭터의 반복 위치 갱신을 중단합니다. 친구가 오프라인이 되면 걷기를 멈추고, 눈을 감은 채 졸음 표시와 작은 숨쉬기 동작을 보여줍니다. 공중에 있다면 잠든 채로 중력을 받아 가까운 가장자리로 떨어지고, 착지한 뒤에는 제자리에서 쉽니다. 다시 접속하면 걷기를 재개합니다. 잠든 캐릭터도 직접 드래그해 옮기거나 던질 수 있고 채팅 입력창은 내 캐릭터를 눌러 열 수 있으며, 모니터 크기에 맞춘 위치 조정과 마우스 위치 조회, 친구 상태 수신은 유지됩니다. OS의 동작 줄이기 설정을 켜면 숨쉬기와 졸음 표시의 반복 효과도 중단합니다.

데스크톱 앱의 **친구들 → 캐릭터 선택**에서 나와 친구의 캐릭터를 각각 선택할 수 있습니다. **내 캐릭터만**으로 화면을 줄이거나 **모두 선택**으로 되돌릴 수 있습니다. 선택 해제한 캐릭터와 그 말풍선은 바탕화면에서 숨겨지지만, 친구 목록은 사이드바에 남습니다. 선택을 모두 해제하면 바탕화면 캐릭터의 애니메이션과 마우스 위치 조회도 중단합니다. 전체 **캐릭터 숨기기 / 표시**는 선택한 대상을 유지한 채 표시만 전환합니다.

캐릭터 선택은 이 기기의 서버·프로필별로 저장합니다. 같은 기기에서 프로필을 다시 선택하거나 카카오 로그인으로 토큰이 바뀌어도 선택을 유지하며, 다른 프로필·서버·기기의 선택에는 영향을 주지 않습니다. 새 친구는 기본으로 선택됩니다. 네트워크가 끊겨도 선택을 바꿀 수 있습니다. 저장에 실패하면 화면에는 적용하고 오류를 안내하며, 저장된 값을 읽지 못하면 모두 선택한 기본값과 안내를 표시합니다. 읽기 실패만으로 기존 저장값을 덮어쓰지 않습니다.

**× 버튼과 창 닫기는 사이드바만 숨깁니다.** macOS 메뉴 막대 또는 Windows 알림 영역의 Wappy 아이콘에서 **사이드바 열기**, **잠깐 쉬기 / 다시 걷기**, **캐릭터 숨기기 / 표시**를 사용할 수 있습니다. 트레이와 사이드바는 같은 설정을 제어합니다. **Wappy 종료**를 선택하면 캐릭터 창과 프로세스까지 함께 종료됩니다. 숨긴 상태에서 앱을 다시 실행하면 기존 사이드바가 나타나며 중복 실행되지 않습니다. macOS에서는 Dock 아이콘으로도 다시 열 수 있습니다.

데스크톱 앱의 첫 화면 또는 **내 모습 → 다음에도 함께 시작해요**에서 **컴퓨터 로그인 시 Wappy 실행**을 켤 수 있습니다. 최초 실행만으로 등록하지 않으며, 사용자가 선택할 때 현재 OS 사용자에게만 등록합니다. 자동으로 시작할 때는 사이드바를 숨기고 트레이와 캐릭터 창을 실행합니다. 캐릭터의 움직임·표시 설정과 마지막에 선택한 프로필은 유지됩니다. 자동 실행이 중복 요청되어도 숨긴 사이드바를 열지 않으며, 직접 앱을 실행하거나 트레이를 선택하면 다시 열립니다.

설정 화면을 열거나 앱으로 돌아오면 OS의 등록 상태를 다시 읽습니다. 변경이 실패해도 상태를 다시 확인하며, 상태를 읽지 못하면 선택을 잠그고 **자동 실행 상태 다시 확인**을 제공합니다. 앱을 사용할 위치에 설치한 뒤 켜고, 앱을 옮기기 전에는 꺼 주세요. macOS에서는 사용자 `Library/LaunchAgents/com.wappy.client.plist`에 등록하며 OS의 백그라운드 실행 허용은 별도로 적용될 수 있습니다. Windows에서는 현재 사용자의 `Run` 항목에 경로를 따옴표로 감싸 등록하고, 작업 관리자의 해당 앱 시작 허용 상태도 확인합니다. 컴퓨터 전체의 시작 설정은 변경하지 않습니다. [Apple Launch Agents](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html), [Microsoft Run 키](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)

Windows 제거 프로그램은 삭제하는 앱의 실행 경로를 가리키는 자동 실행 등록과 작업 관리자 설정을 함께 정리합니다. 업데이트 모드와 기존 앱을 지우지 않는 재설치에서는 기존 설정을 유지하며, 다른 설치 경로를 가리키는 등록은 지우지 않습니다. 설치 중 기존 앱을 먼저 제거하는 옵션을 선택했다면 다시 설치한 뒤 자동 실행을 켜 주세요. macOS에서 앱을 삭제할 때는 자동 실행을 먼저 꺼 주세요.

캐릭터 창은 사이드바와 일반 앱 창보다 앞에 표시됩니다. 사이드바를 클릭하거나 고정 설정을 바꿔도 캐릭터가 그 뒤로 가려지지 않습니다.

사이드바는 처음에 현재 모니터의 작업 영역 오른쪽에 배치되며, 화면 배율·작업 표시줄·Dock을 고려합니다. 상단 로고와 빈 공간을 드래그해 옮길 수 있고, 접은 상태에서는 위쪽의 **⠿** 손잡이를 드래그하면 됩니다. 접거나 펼치면 현재 모니터 오른쪽으로 다시 정렬됩니다. 항상 위에 표시 설정은 상단 버튼으로 바꿀 수 있습니다.

## 도움말과 문제 신고

첫 화면, 서버 없는 체험, 로그인 후 **내 모습**의 **도움말·앱 정보**에서 문제 확인 정보를 미리 보고 복사할 수 있습니다. 설치된 앱의 버전·빌드 식별자, 운영체제 구분, 연결 상태, 서버 종류와 캐릭터 표시·움직임 설정만 포함합니다. 이름·친구 목록·프로필 ID·서버 주소·로그인 토큰·초대장은 포함하지 않습니다. 브라우저에서는 프런트엔드 버전과 브라우저 실행 여부를 표시하며, 네이티브 버전을 읽지 못하면 확인할 수 없다고 표시합니다.

CI 설치 파일의 빌드 식별자는 해당 커밋 SHA의 앞 12자리입니다. 같은 앱 버전의 테스트 빌드도 구분할 수 있습니다. 직접 빌드할 때는 `VITE_BUILD_ID`에 소스의 40자리 커밋 SHA를 지정할 수 있으며, 생략하거나 잘못된 형식을 넣으면 식별 정보가 없다고 표시합니다. 이 값은 앱에 포함되는 공개 정보이므로 비밀값을 넣지 마세요. Turborepo는 Vite의 `VITE_*` 환경 변수를 작업 해시에 자동 반영하므로 식별자가 다른 빌드를 같은 캐시로 재사용하지 않습니다.

**문제 확인 정보 복사** 후 **GitHub에서 문제 신고**를 눌러 발생 상황과 함께 직접 붙여넣어 주세요. 복사나 페이지 열기에 실패하면 선택된 내용을 직접 복사하거나 **신고 주소 복사**로 기본 브라우저에 주소를 붙여넣을 수 있습니다. GitHub 로그인이 필요하며 작성한 이슈는 공개되므로 개인정보나 코드를 담은 화면은 올리지 마세요. 도움말을 열거나 정보를 복사하는 것만으로 전송·신고하지 않습니다.

데스크톱 앱의 링크 열기 권한은 메인 창에서 Wappy의 고정된 신고 페이지를 기본 브라우저로 여는 동작에만 부여합니다. 다른 주소, URL에 추가한 내용, 파일 경로, 지정한 외부 프로그램과 캐릭터 창의 링크 열기는 허용하지 않습니다. [Tauri Opener 권한](https://v2.tauri.app/plugin/opener/#permissions)

저장소의 `.github/ISSUE_TEMPLATE/bug_report.yml`은 현상·재현 방법·문제 확인 정보를 받는 신고 양식입니다. GitHub에서는 이 파일이 기본 브랜치에 반영된 뒤 양식을 사용할 수 있습니다. 앱의 신고 링크는 특정 양식이나 미리 채운 진단 정보 없이 이슈 작성 화면으로 이동합니다.

## 구조와 공통 API

| 경로           | 역할                                                                 |
| -------------- | -------------------------------------------------------------------- |
| `apps/client`  | React 관리 사이드바, Tauri 투명 캐릭터 창, 기기 내 세션 저장         |
| `apps/server`  | Node HTTP API, SQLite 영속 저장, 접속 상태                           |
| `packages/api` | `@wappy/api`: 메서드·경로별 요청/응답 타입, 캐릭터 목록, 프로필 검증 |

클라이언트의 `request()`와 서버의 `reply()`가 같은 `ApiRoutes`를 참조합니다. 타입 변경은 두 앱의 타입 검사에 반영되며, 서버는 외부 JSON을 런타임에도 검증합니다. 모든 요청과 응답은 JSON입니다.

| 메서드·경로            | 요청                          | 응답                                                           |
| ---------------------- | ----------------------------- | -------------------------------------------------------------- |
| `POST /session`        | `{ name, character }`         | `{ token, profile }` (201)                                     |
| `GET /state`           | 없음                          | `{ self, friends: [{ id, name, character, online }] }`         |
| `POST /chat`           | `{ text }`                    | `{ id, senderId, text, sentAt }` (201)                          |
| `PATCH /profile`       | `{ name, character }`         | 프로필                                                         |
| `PATCH /presence`      | `{ sharing }`                 | `{ sharing, revision }`                                        |
| `POST /invites`        | `{}`                          | `{ code }` (201)                                    |
| `POST /invites/preview` | `{ code }`                   | `{ name, character }`                               |
| `POST /invites/accept` | `{ code }`                    | 초대 코드를 발급한 참여자의 프로필                                           |
| `POST /friends/remove` | `{ friendId }`                | `{ ok: true }`                                                 |
| `POST /friends/block`  | `{ friendId }`                | `{ revision, profiles: [{ id, name, character }] }`            |
| `POST /friends/unblock`| `{ friendId }`                | `{ revision, profiles: [{ id, name, character }] }`            |
| `POST /friends/attack` | `{ friendId }`                | `{ id, attackerId, targetId, sentAt }` (201)                     |
| `GET /health`          | 없음                          | `{ ok: true }`                                                 |

`POST /session`, `POST /invites/preview`, `GET /health`, CORS preflight를 제외한 요청은 `Authorization: Bearer <token>`이 필요합니다. 오류는 `{ error: string }`과 400/401/403/404/409/413/415/429/500 상태 코드로 반환합니다. 이름은 1–24자, 캐릭터는 공통 API의 `CHARACTERS`에 등록된 20종 중 하나입니다. 산리오 캐릭터 ID는 `pochacco`, `badtz-maru`, `hangyodon`, `pekkle`, `tuxedosam`, `keroppi`입니다. 서버와 참여하는 앱을 함께 업데이트하세요. 서버 시작 시 기존 프로필의 상태 메시지 열을 삭제하며, 이름·캐릭터·로그인 정보·친구 연결은 유지합니다. 삭제된 기본 캐릭터 6종의 기존 프로필·차단 목록은 서버 시작 시 `chiikawa`로 전환되며, 기기에 저장된 프로필이나 이전 서버 응답도 치이카와로 표시합니다. 새 프로필 생성·수정 요청에는 현재 등록된 캐릭터만 허용합니다.

새 초대 코드는 영문 대문자·숫자 5자리이며 혼동하기 쉬운 `I`, `O`, `0`, `1`을 제외합니다. 소문자로 입력해도 사용할 수 있고, 인원과 기간 제한 없이 여러 사람이 같은 코드로 연결할 수 있습니다. 초대 코드는 방에 연결됩니다. 방이 없으면 첫 코드 발급 때 방을 만들고, 참여자 누구나 현재 방의 코드를 새로 발급할 수 있습니다. 수락해도 코드는 유지되며, 새 코드를 만들면 그 방의 이전 코드가 모두 무효화됩니다. 코드가 겹치면 다른 코드를 발급합니다. 같은 방의 본인 초대와 중복 참여는 거부하며, 초대·차단 확인과 기존 방 탈퇴·새 방 참여·참여자 간 연결을 하나의 SQLite 트랜잭션으로 처리합니다. 실패하면 기존 방과 친구·채팅 기록을 유지합니다. 서버 업데이트 시 DB에 남아 있는 기존 43자리 코드도 만료 제한 없이 사용할 수 있습니다. 이미 삭제된 코드는 복원하지 않습니다. 5자리·무제한 초대를 사용하려면 서버와 앱을 함께 업데이트해야 합니다. 연결 해제는 양쪽 목록에 반영됩니다.

`GET /state`의 `room: { id, name }`은 현재 참여 중인 방입니다. 아직 방이 없거나 이전 서버에 연결한 경우 생략됩니다. 다른 방으로 이동하면 이전 방의 친구 연결과 해당 연결의 채팅 수신 기록·공격이 정리되며, 새 방 참여 전 메시지는 받지 않습니다. 기존 친구 연결 해제·차단은 개별 상대에게 적용되고 방 참여 자체는 유지됩니다.

기존 데이터에는 누가 어떤 초대를 수락했는지 남아 있지 않으므로, 첫 업데이트 때 친구 관계로 이어진 각 그룹을 하나의 방으로 이관합니다. 같은 그룹의 참여자끼리 연결하되 차단은 유지하며, 서로 연결되지 않은 그룹은 별도 방으로 남습니다. 기존 초대 코드는 해당 그룹의 방을 가리키고 새로 발급하기 전까지 모두 유지됩니다. 이관은 한 번만 수행하며 새로 연결된 상대에게 과거 채팅을 공개하지 않습니다.

초대 미리보기는 유효한 코드를 가진 사람에게 초대한 프로필의 현재 이름·캐릭터만 보여 줍니다. 로그인 정보·프로필 ID·상태 메시지·친구 목록·접속 상태·복구 코드는 반환하지 않습니다. 확인만으로 친구를 연결하거나 접속 상태를 갱신하지 않으며, 재발급으로 무효화된 코드는 미리볼 수 없습니다. 앱은 붙여넣기만으로 요청하지 않고 **초대장 미리 확인하기**를 누를 때 확인하며, 기존 로그인 토큰을 보내지 않습니다. 코드나 서버를 바꾸면 이전 확인 결과를 사용하지 않습니다.

**초대받았어요**에서는 미리보기를 확인해야 새 프로필을 만들 수 있고, 만들기 직전에 서버에서 초대를 다시 확인합니다. 이때 재발급으로 무효화된 코드이면 프로필을 생성하지 않습니다. 확인 직후 초대한 사람이 코드를 다시 발급하면 프로필 생성 후 연결이 실패할 수 있습니다. 생성한 프로필은 유지되며 새 초대로 다시 연결할 수 있습니다. 초대 미리보기와 이 시작 흐름을 사용하려면 서버도 해당 기능이 포함된 버전으로 업데이트해야 합니다.

`POST /friends/attack`은 인증한 프로필을 공격자로 사용하고, 친구 관계·양방향 차단·두 사람의 공개 접속 상태를 확인합니다. 친구가 아니면 404, 접속 숨김·오프라인이면 409, 공격 간격이 너무 짧으면 429와 `Retry-After`를 반환합니다. `GET /state`의 선택 필드 `attacks`에는 본인이 공격자 또는 대상인 최근 15초의 이벤트를 ID 순서로 최대 50개 포함합니다. 제3자에게는 전달하지 않으며 만료 시 ETag도 갱신합니다. 필드가 없는 이전 서버에서는 공격을 보내지 않습니다. 친구 삭제·차단 시 관련 이벤트는 함께 삭제됩니다. 로그인 토큰은 메인 창에만 두고, 바탕화면 창은 공격 요청과 확인된 상태만 주고받습니다.

`GET /state`의 최상위 `presence: { sharing, revision }`은 인증한 프로필 자신의 접속 공개 설정입니다. 친구의 설정이나 마지막 접속 시각은 응답에 포함하지 않습니다. 숨긴 프로필은 계속 조회하거나 채팅을 보내도 친구의 `online`이 `false`이며, 다시 공개하면 마지막 통신 시각에 따른 일반 접속 상태로 돌아갑니다. `/presence`는 본인의 설정만 변경하고, `/profile`이나 카카오 로그인은 이를 변경하지 않습니다. `revision`은 변경할 때마다 증가하여 늦은 조회 응답이 최근에 확인한 설정을 덮어쓰지 않게 합니다.

`GET /state`의 `messages`는 인증한 프로필이 볼 수 있는 최근 전체 메시지이며 ID 오름차순입니다. `/chat`에 `friendId` 또는 `recipientId`를 넣으면 400으로 거절합니다. 삭제된 개인 채팅·신고·읽음 처리 API는 404를 반환합니다. 기존 SQLite의 전체 메시지는 유지하고 개인 메시지는 전체 채팅 응답에서 제외합니다. 이전 서버에 연결한 클라이언트도 개인 메시지를 말풍선으로 표시하지 않습니다.

`GET /state`의 `blocking: { revision, profiles }`는 인증한 사용자가 차단한 프로필의 목록입니다. 필드가 없으면 차단 기능을 지원하지 않는 서버입니다. `/friends/block`는 현재 서버에 존재하는 다른 프로필 ID를 대상으로 본인의 차단 기록과 친구·대화 정리를 한 트랜잭션으로 처리합니다. 본인 차단은 400, 없는 프로필은 404입니다. `/friends/unblock`는 본인이 만든 차단만 해제합니다. 반복 요청은 안전하며 실제 목록 변경 때만 `revision`을 올립니다. 클라이언트는 이전 revision의 조회·변경 응답이 최근 차단을 덮어쓰지 못하게 합니다. 초대 수락 시 초대 코드를 발급한 사람과 양방향 차단 관계이면 409로 거절하며, 초대장 자체는 유지합니다. 다른 참여자와의 차단도 유지되어 같은 방에 들어가더라도 해당 상대의 프로필·채팅·공격은 전달되지 않습니다. 공개 초대 미리보기에는 기존과 동일하게 이름·캐릭터만 표시합니다.

기본 서버에서는 5자리 코드만 복사하며, 별도 서버에서는 서버 주소와 코드가 담긴 초대장을 복사합니다. 로그인 토큰은 포함하지 않습니다. 별도 서버의 코드만 받았다면 서버 주소를 직접 맞춰야 합니다. 이미 로그인한 프로필은 다른 서버의 초대장을 받아도 서버를 바꾸거나 토큰을 보내지 않고 안내합니다. 첫 친구 연결에 실패해도 생성한 프로필은 유지되므로 초대 화면에서 코드를 확인하고 다시 시도할 수 있습니다. 응답을 받지 못했다면 **친구들** 목록에서 연결 여부도 확인하세요.

상태는 5초 간격으로 가져오며 마지막 조회로부터 30초가 지나면 오프라인으로 표시됩니다. **데스크톱 앱은 Rust 백그라운드 작업에서 조회하므로 사이드바의 숨김·최소화와 WebView 타이머 제한에 의존하지 않습니다.** 네트워크가 끊기면 재시도하고 오래된 접속 상태를 온라인으로 표시하지 않습니다. 컴퓨터 자체가 잠자기 상태에 들어가거나 네트워크가 끊긴 동안에는 오프라인으로 표시되며, 다시 통신할 수 있게 되면 자동으로 갱신됩니다. 브라우저 미리보기는 웹 타이머로 조회하므로 브라우저의 백그라운드 제한이 적용될 수 있습니다.

데스크톱·브라우저 조회 요청은 10초 안에 완료되지 않으면 취소하고 재시도합니다. 연속 실패 시 재시도 간격은 5·10·20·40·60초까지 늘어나며 성공하면 다시 5초 간격으로 돌아옵니다. 응답은 최대 1MiB까지 받으며, 캐릭터·프로필·친구 목록의 형식을 확인한 뒤 화면에 반영합니다. 인증 토큰을 다른 곳으로 보내지 않도록 상태 조회의 HTTP 리디렉션은 따라가지 않으므로 최종 서버 주소를 입력하세요. 인증이 만료되면 재시도를 멈추고 시작 화면으로 이동하도록 안내합니다. 계정 변경, 페이지 새로고침, 앱 종료 시 이전 조회 작업이 중단됩니다.

서버가 ETag를 지원하면 상태가 그대로인 조회는 본문 없는 304 응답을 사용합니다. 접속 유지는 계속하면서 JSON 파싱과 두 창의 불필요한 상태 갱신을 생략합니다. 서버는 최대 1,024개의 작은 검증 정보만 보관하고, 데이터 변경·친구 접속 변화·채팅 만료를 확인합니다. 이전 서버는 기존 전체 응답 방식으로 사용할 수 있습니다. 재현 가능한 메모리·네트워크 점수와 측정 범위는 [자체 평가 안내](PERFORMANCE.md)를 참고하세요.

서버 접속 상태는 메모리에만 저장하므로 서버 재시작 직후에는 각 앱이 다시 조회할 때 갱신됩니다. 단일 서버 프로세스를 기준으로 합니다.

## 서버 설정과 데이터

Docker로 실행하거나 친구가 접속할 HTTPS 서버를 준비하려면 [서버 배포·백업 안내](apps/server/README.md)를 따르세요. `docker compose up -d --build --wait`로 로컬 API를 실행할 수 있으며 데이터는 별도 볼륨에 보관합니다.

앱의 첫 화면 **연결할 서버**, 로그인 후 **내 모습 → 함께할 서버**에서 **서버 연결 확인**을 누르면 프로필을 만들기 전에 응답을 확인할 수 있습니다. 버튼을 눌렀을 때만 공개 상태 확인 요청을 한 번 보내며, 로그인 토큰·쿠키를 보내거나 다른 주소로의 리다이렉트를 따라가지 않습니다. 확인은 프로필·친구·접속 상태를 바꾸지 않습니다.

잘못된 주소, 서버 오류, 예상과 다른 응답, 연결 실패와 10초 초과 대기를 구분해 안내합니다. 주소를 바꾸거나 화면을 떠나면 진행 중인 확인을 취소하고, 이전 주소의 결과를 재사용하지 않습니다. `localhost`처럼 내 컴퓨터를 가리키는 주소에는 다른 기기의 친구가 사용할 공용 주소가 필요하다고 안내합니다. 성공은 확인한 시점의 서버 응답을 뜻하며, 로그인·프로필 생성·친구 연결의 성공을 보장하지 않습니다.

`apps/server/.env.example`을 `apps/server/.env`로 복사해 설정할 수 있습니다.

| 변수              | 기본값                | 설명                                 |
| ----------------- | --------------------- | ------------------------------------ |
| `HOST`            | `127.0.0.1`           | 외부 연결을 받으려면 `0.0.0.0` 사용  |
| `PORT`            | `3001`                | API 포트                             |
| `DATABASE_PATH`   | `./data/wappy.sqlite` | 서버 작업 디렉터리 기준 SQLite 경로  |
| `ALLOWED_ORIGINS` | 없음                  | 추가 웹 클라이언트 Origin, 쉼표 구분 |
| `TRUST_PROXY`     | 꺼짐                  | 신뢰하는 단일 프록시 뒤에서만 `1` 사용 |

Tauri의 macOS·Windows Origin과 로컬 Vite Origin은 기본 허용됩니다. 운영 서버는 HTTPS 리버스 프록시 뒤에 두고, 친구 모두 접근할 수 있는 **동일한 서버 주소**를 사용하세요. 클라이언트 기본 주소는 `https://wappy-api.waps.im`이며, `apps/client/.env`의 `VITE_API_URL` 또는 최초 화면의 **연결할 서버**에서 바꿀 수 있습니다. 로컬 개발 서버를 사용하려면 `VITE_API_URL=http://localhost:3001`로 설정하세요. `localhost`는 각자의 컴퓨터이므로 서로 다른 기기에서 사용할 공용 서버 주소가 아닙니다. 서버는 자동으로 배포되지 않습니다.

```sh
pnpm build
pnpm --filter server start
```

서버는 별도 프레임워크나 DB 서비스 없이 Node의 [내장 SQLite](https://nodejs.org/api/sqlite.html)를 사용합니다. 사용자·친구·유효한 초대·접속 공개 설정은 SQLite에 저장하며 세션 토큰과 초대 코드는 SHA-256 해시로만 저장합니다. 기존 데이터베이스는 시작 시 필요한 테이블을 추가하며, 사용하지 않는 복구 코드 테이블은 삭제합니다. 기존 프로필·로그인 정보·친구 연결은 유지합니다. 쓰기 요청은 4KB로 제한하고 IP별 요청 횟수를 제한합니다. 프로필 생성·카카오 로그인 시작 요청은 합산하여 분당 10회, 초대 미리보기는 별도로 분당 60회, 나머지 쓰기 요청은 분당 60회까지 허용합니다. 미리보기 횟수는 프로필 생성·변경의 허용 횟수를 소비하지 않습니다. 기본값에서는 프록시의 전달 헤더를 무시합니다. 제공하는 HTTPS 구성은 API 포트의 직접 접근을 막고 `TRUST_PROXY=1`로 단일 프록시가 전달한 마지막 유효 IP를 사용합니다. 다른 프록시를 사용할 때도 [접근 조건](apps/server/README.md)을 확인하세요.

클라이언트의 기기별 토큰은 로컬 WebView 저장소에 남습니다. 앱 재실행 시 같은 프로필로 돌아옵니다. 브라우저·Tauri 개발 모드·빌드된 앱은 서로 다른 Origin의 저장소를 사용합니다. 카카오로 만든 프로필은 같은 서버에서 같은 카카오 계정으로 다시 로그인할 수 있습니다. 이름으로 만든 프로필은 기기에 저장된 로그인 정보를 잃으면 다시 불러올 수 없습니다. 이메일 로그인은 제공하지 않습니다.

서버를 바꿀 때 현재 프로필의 로그인 정보와 표시할 이름을 이 기기에 보관합니다. 같은 서버의 서로 다른 프로필도 별도로 보관하며, 카카오 로그인으로 토큰이 교체되면 해당 프로필의 보관 정보만 갱신합니다. 보관에 실패하면 현재 연결을 유지합니다. 선택한 프로필만 접속 상태를 갱신하고, 보관한 나머지 프로필은 조회하지 않습니다. 보관된 프로필은 앱을 다시 실행해도 남지만, 기기 저장소가 지워지면 함께 사라집니다.

첫 화면에서 **이 기기에서 보관 해제 → 보관 해제 확인**을 선택하면 해당 로그인 정보만 기기에서 지웁니다. 서버의 프로필과 친구 목록은 유지됩니다. 카카오로 만든 프로필은 같은 계정으로 다시 로그인할 수 있지만, 이름으로 만든 프로필은 다른 유효한 로그인 정보가 없으면 다시 불러올 수 없습니다. 인증이 만료되면 **시작 화면으로 이동**에서 다시 로그인하거나 보관한 다른 프로필을 선택할 수 있습니다.

카카오로 다시 로그인할 때마다 세션 토큰을 교체하므로 기존 기기는 인증이 만료되고 수정 요청도 거부됩니다. **한 프로필의 활성 로그인 토큰은 하나**입니다. 서버 백업 시 실행을 중지한 뒤 데이터 디렉터리 전체를 보관하세요.

## 빌드와 검증

```sh
pnpm build
pnpm check-types
pnpm test
pnpm lint
cargo fmt --manifest-path apps/client/src-tauri/Cargo.toml --check
cargo check --manifest-path apps/client/src-tauri/Cargo.toml
cargo test --manifest-path apps/client/src-tauri/Cargo.toml --lib --locked
pnpm --filter client tauri build
```

Tauri 패키지는 해당 운영체제에서 빌드합니다. `.github/workflows/check.yml`은 macOS·Windows 각각에서 타입 검사, 빌드, API 통합 테스트, Rust 테스트와 실제 창·트레이·백그라운드 연결 검사를 실행한 뒤 설치 프로그램을 만듭니다. Windows에서는 이어서 공백·한글 경로에 실제 설치하고 배포용 앱의 창이 열리는지 확인합니다. 설치만으로 자동 실행을 켜지 않는지, 업데이트 모드(`/UPDATE`)와 덮어쓰기 재설치 시 작업 관리자 설정을 유지하는지, 제거 시 해당 설치의 자동 실행 항목만 정리하는지도 검사합니다. 이 설치 검사는 폐기되는 GitHub 호스팅 Windows 러너에서만 실행합니다. 한 운영체제의 실패가 다른 운영체제의 검사를 취소하지 않습니다.

GitHub Actions의 **Check Wappy → Artifacts**에서 해당 커밋의 테스트용 설치 파일을 받을 수 있습니다. macOS는 Apple Silicon·Intel을 모두 담은 **universal DMG**, Windows는 **x64 NSIS 설치 프로그램**입니다. Windows 설치는 현재 사용자에게 적용하고 한국어·영어를 선택할 수 있습니다. WebView2가 없으면 설치 과정에서 내려받으므로 인터넷 연결이 필요합니다. 아티팩트는 7일 동안 보관하며, 워크플로를 수동으로 다시 실행할 수도 있습니다. [Tauri Windows 설치 프로그램](https://v2.tauri.app/distribute/windows-installer/), [macOS DMG](https://v2.tauri.app/distribute/dmg/)

이 파일들은 개발자 배포 서명·Apple 공증이 없는 테스트용 빌드입니다. 일반 사용자에게 배포하기 전에는 해당 인증서를 설정하고 설치·업데이트·삭제를 실제 기기에서 검증해야 합니다. 워크플로는 GitHub Release를 발행하거나 서버를 배포하지 않습니다. 설치한 앱에서 친구와 같은 서버 주소를 입력하세요.

로컬에서 두 macOS 아키텍처를 함께 빌드하려면 다음 명령을 사용합니다. Windows에서는 해당 OS에서 `pnpm --filter client tauri build --ci --target x86_64-pc-windows-msvc`를 실행하면 `apps/client/src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/`에 설치 파일이 생성됩니다.

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
CI=true pnpm --filter client tauri build --ci --target universal-apple-darwin
```

macOS 결과물은 `apps/client/src-tauri/target/universal-apple-darwin/release/bundle/dmg/`에 생성됩니다. `CI=true`는 Finder 자동화 권한이 필요한 DMG 창 꾸미기를 생략합니다. DMG를 열고 Wappy를 Applications 폴더로 옮겨 사용하세요.

화면이 켜진 실제 데스크톱 세션에서는 프런트엔드 빌드 후 다음 검사로 트레이 생성, 닫기 후 숨김, 숨긴 상태의 제어 이벤트, 일시정지 시 애니메이션 프레임 중단과 다시 걷기 시 재개, 두 번째 실행 시 기존 창 복원, 최소화 복원과 종료를 확인할 수 있습니다. WebView의 타이머를 비활성화한 채 로컬 테스트 서버를 조회하여 접속 상태 갱신, 오류 후 재연결, 숨긴 사이드바의 접속 숨김 설정 표시와 친구 캐릭터 렌더링, 캐릭터 개별 선택·전체 선택 해제와 보관한 프로필의 선택 복원, 프로필 보관 후 말풍선 숨김과 조회 중단 및 재선택 후 재개, 세션 삭제 후 조회 중단도 확인합니다. 별도 앱 식별자와 비공개 WebView 저장소를 사용하므로 기존 프로필을 읽거나 변경하지 않습니다. 검사 전용 자동 실행 항목을 잠시 등록했다가 제거하며 실제 Wappy의 자동 실행 설정은 건드리지 않습니다. 잠시 테스트 창과 트레이 아이콘이 나타났다가 종료됩니다.

```sh
cargo run --manifest-path apps/client/src-tauri/Cargo.toml --example lifecycle --features tauri/custom-protocol --locked
cargo run --manifest-path apps/client/src-tauri/Cargo.toml --example lifecycle --features tauri/custom-protocol --locked -- --autostart
```

macOS의 투명 창은 `macOSPrivateApi` 설정과 `macos-private-api` Cargo 기능을 사용하므로 현재 빌드는 직접 배포를 전제로 합니다. Tauri 문서는 이 방식의 Mac App Store 수용 불가를 명시하고, Apple 심사 지침 2.5.1은 공개 API만 허용합니다. Mac App Store용으로 출시하려면 바탕화면 캐릭터 경험을 유지할 수 있는 공개 API 렌더링 방식을 별도로 구현·검증해야 합니다. 설정 하나를 끄거나 사이드바만 남긴 빌드로 같은 기능을 제공한다고 볼 수 없습니다. [Tauri 투명 창 설정](https://v2.tauri.app/reference/config/#transparent), [Apple 소프트웨어 요구사항](https://developer.apple.com/app-store/review/guidelines/#software-requirements)

macOS에서 아래 명령은 공개 AppKit API로 대체 렌더링이 가능한지 검사합니다. 기존 `Character.tsx`에서 공통 캐릭터 목록에 등록된 20종의 접속·오프라인 SVG 40개를 생성하고, 별도 Swift 검사 프로그램이 이를 실제 투명 `NSWindow`/`NSView`에 그립니다. 새 그림 파일을 따로 유지하지 않으며 기존 캐릭터를 그대로 사용합니다. 잠시 나타나는 검사 창은 키보드 초점을 가져가지 않습니다. 프로필이나 WebView 저장소를 읽지 않고 화면 녹화·손쉬운 사용 권한도 요청하지 않습니다.

```sh
pnpm --filter @wappy/api build
pnpm --filter client check-public-overlay
```

검사는 네 방향 회전·좌우 반전·한글 이름표, 창의 투명 설정과 렌더링 결과의 알파 값, 캐릭터 영역 판정, 해당 창에 직접 전달한 클릭·드래그 이벤트, 클릭 통과 설정 전환을 확인합니다. 성공하면 출력한 임시 디렉터리에 `public-overlay.png`와 `result.json`을 남깁니다. Node 의존성과 macOS Xcode Command Line Tools가 필요합니다.

이 검증용 렌더러는 아직 앱의 바탕화면 창에 연결하지 않았습니다. 실제 적용에는 기존 이동·던지기 물리, 말풍선·친구 상태·선택 동기화, 접근성, 여러 모니터 및 다른 앱으로의 실제 클릭 통과 검증이 남아 있습니다. 현재 앱의 비공개 API 사용이나 Mac App Store 출시 제약은 이 검사 통과만으로 해결되지 않습니다.

채팅을 제공하는 공개 서비스에는 사용자 차단 외에도 부적절한 콘텐츠 필터링, 신고 접수와 적시 대응, 공개 연락처가 필요합니다. 현재 메시지 신고·검토 기능과 콘텐츠 게시 전 필터링·운영 담당자·대응 시간·공개 연락처는 준비되어 있지 않습니다. GitHub 문제 신고는 제품 오류 제보용이며 콘텐츠 신고 운영을 대신하지 않습니다. 스토어 심사 통과나 순위 확률은 현재 기능 검사 결과로 입증되지 않습니다. [Apple 사용자 생성 콘텐츠 지침](https://developer.apple.com/app-store/review/guidelines/#user-generated-content)
